# nakedlunch

Офлайн-генератор песенных строк-заготовок. Русский язык, macOS, ноль сети.

Генератор тупой (грамматика + морфология + разметка ударений), фильтр умный —
каскад отсева по рифме, слогам, клаузуле, банальности, сцепке слов, тавтологии,
мату, чёрному списку и истории показов. Никакой нейросети-автора, ни одного
внешнего вызова: всё считается на CPU из локальных таблиц.

Второй источник строк — **корпус**: настоящие тексты, нарезанные на фрагменты
(2.4 млн на машине автора), из которых отбор достаёт готовые куски. Их можно
смешивать с генерацией одной крутилкой.

Инструмент личный: писался под одного человека и под его способ работы. Здесь
он выложен как есть.

---

## Что нужно

| | |
|---|---|
| Python | 3.12 |
| Node | 20+ (для сборки интерфейса — `launch.py` соберёт сам) |
| ОС | macOS (нативное окно через pywebview; без него откроется в браузере) |
| Диск | ~1.6 ГБ под индексы, если собирать корпус |
| Сеть | не нужна нигде, кроме первой установки зависимостей |

## Установка

```sh
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python launch.py
```

`launch.py` соберёт фронтенд (`npm install && npm run build`, если `dist/` нет
или он старше исходников), поднимет Flask на свободном порту и откроет окно.
Двойной клик по `run.command` делает то же самое.

Программа стартует сразу: генератор работает на своих таблицах
(`core/data/forms.json`, `lexicon.json` — они в репозитории). Корпус, рифмы по
слову и семантика темы требуют артефактов, которых в git нет — см. «Сборка
артефактов».

## Данные

Их в репозитории нет и не будет — это работа владельца, а не код.

| где | что |
|---|---|
| `data/` | личный корпус принятых строк, история показов, избранное, положения крутилок, полки профилей, логи, статистика прогонов |
| `~/Documents/nakedlunch/data` | нарезанные фрагменты источников (у автора 526 МБ) |
| `~/Documents/nakedlunch/тексты` | листы редактора |
| `~/Documents/nakedlunch/записи` | записи голоса |

Пути переопределяются переменными среды `NAKEDLUNCH_DATA`, `NAKEDLUNCH_VAULT`,
`NAKEDLUNCH_RECORDINGS` — этим же приёмом проверяют заливку книг на временном
корпусе, не трогая настоящий.

## Сборка артефактов

Тяжёлые таблицы в git не едут: вместе они около 1.6 ГБ и пересобираются из
`tools/`. Порядок важен — каждый шаг читает результат предыдущего.

Сборка ударений требует зависимостей, не нужных самому приложению:

```sh
pip install ruaccent "transformers<5"
```

Пятёрка обязательна: ONNX-вызов ruaccent ломается на transformers 5.x.

**Для рифм по слову** — попап «чем зарифмовать», клаузула, буквы рифмовки в
редакторе. Нужно всем, даже без корпуса:

```sh
python tools/build_rhyme_index.py   # → core/data/rhyme_index.json, 66 МБ, ≈4 мин
```

**Для корпуса** — если работаешь с нарезанными источниками:

```sh
python tools/build_nl_rhyme.py      # → core/data/nl_rhyme.jsonl, часы на 2.4 млн
python tools/build_nl_index.py      # → core/data/nl_index/, ≈160 с
```

Порядок важен: индекс печётся из кэша ударений.

**Словарь генератора** (`lexicon.json`, `forms.json`) лежит в репозитории
готовым — пересобирать нужно, только если расширяешь словарь:

```sh
python tools/build_lexicon.py
python tools/build_forms.py
```

**Модель векторов.** `core/data/navec.tar` (51 МБ, MIT) в репозиторий не
положен — это чужая работа со стабильной ссылкой. Без него всё работает, кроме
семантики темы (строки перестают подбираться по смыслу и подбираются только по
буквальному совпадению слов). Взять
[navec_hudlit_v1_12B_500K_300d_100q.tar](https://github.com/natasha/navec)
и положить как `core/data/navec.tar`.

## Полезные ключи сборщиков

```sh
python tools/build_nl_index.py --check   # сверить версию правил, не пересобирая
python tools/build_nl_rhyme.py --reban   # пересчитать качество потоком (292 МБ пика)
python tools/build_nl_rhyme.py --jsonl   # разовая миграция старого кэша в построчный
```

## Устройство

```
core/       домен: генерация, разбор, отбор, корпус, индекс. О фронтенде не знает.
  generate.py   грамматический генератор строк
  scan.py       ударения, слоги, рифмо-ключи, клаузула
  filters.py    каскад отсева и отбор шорт-листа
  nlindex.py    колоночный индекс корпуса (mmap) и ворота по нему
  nlsrc/        резка и хранилище фрагментов (внесены из CLI-предшественника)
api/        тонкий Flask-адаптер над core. Логики в нём нет.
interface/  React/Vite-клиент: генератор, редактор, фристайл, пайплайн.
tools/      сборщики таблиц и индексов (офлайн, разово).
tests/      552 теста, включая свойства распределений выдачи.
project-notes/  память проекта: STATE · DECISIONS · BACKLOG · планы.
```

`project-notes/DECISIONS.md` — не changelog, а журнал **почему**: каждое
решение записано вместе с замером, который его выбрал, и с ошибкой, которая
ему предшествовала. Если что-то в коде выглядит странно, ответ почти всегда там.

## Тесты

```sh
.venv/bin/python -m pytest tests/ -q
```

На машине с собранными артефактами — 552 зелёных. На свежем клоне часть тестов
честно пропускается с указанием, чего не хватает: индекса корпуса, словаря рифм
или модели векторов. Пропуск, а не смягчение — там, где артефакт есть, тест
остаётся ровно таким же строгим.

Проверено на чистом клоне без единого артефакта: `494 passed, 58 skipped`.

## Чего здесь нет

- **Windows и Linux.** Окно, ярлык и пути писались под macOS.
- **Английского.** Морфология, ударения, рифма — только русский.
- **Сети.** Ни телеметрии, ни облака, ни API. Это не позиция, а требование:
  инструмент работает в самолёте.
- **Автора-нейросети.** Строки собирает грамматика, а решает — отбор и человек.
