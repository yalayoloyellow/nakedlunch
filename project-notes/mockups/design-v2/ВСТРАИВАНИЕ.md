# Встраивание: что заменить, чтобы приложение заработало на реальных данных

Интерфейс готов. Всё выдуманное содержимое собрано за одной границей, и подменяется
без правки разметки, состояния и логики UI.

## Где граница

Файл `Editor First.dc.html`, в логике компонента — блок `api = { … }` с пометкой
`═══ ГРАНИЦА С БЭКЕНДОМ ═══`. Восемь методов. Ниже него лежат демо-данные
(`STANZAS`, `SYN`, `ANT`, `RHYME`, `POOL`, `CORPUS_TOTAL`) — после встраивания они удаляются
вместе с методами-заглушками `suggestList` и `rhymeTail`.

Интерфейс к демо-данным напрямую не обращается: каждое обращение проходит через `api.*`.

## Восемь методов

| Метод | Что должен вернуть | Где видно в интерфейсе |
|---|---|---|
| `corpusTotal()` | число строк в корпусе | воронка отбора, «корпус» в статистике |
| `corpusSources()` | `[{ name, lines }]` — источники и их объём | статистика |
| `poolSize()` | строк в рабочем пуле после отбора корпуса | воронка отбора |
| `stanzaPool(roleKey)` | заготовки строф для роли звена | генерация строфы, прогон, фристайл |
| `wordSuggest(word, tab, rowIdx)` | `[{ w, n }]` — варианты и подпись справа | попап по клику на слово |
| `rhymeFor(tail)` | одно слово в рифму к окончанию строки | стык звеньев цепочки |
| `runTitles()` | названия вариантов прогона | заголовки блоков прогона |

`roleKey` — `verse` \| `chorus` \| `bridge` (даёт `KEYFOR` по роли звена).
`tab` — `рифмы` \| `по звуку` \| `синонимы` \| `антонимы` \| `строкой`.
`rowIdx` — индекс строки документа: нужен вкладке «строкой», чтобы предложить замену целой строки.

## Формат строфы

`stanzaPool` возвращает массив куплетов. Куплет — массив строк, строка — пара
`[начало, окончание]`: разделение нужно только для рифмовки стыков, склеивается конкатенацией.

```js
[ [ ['в скалах Коктебеля в 1970-', 'ом'], ['там северный Кувейт и Клонд', 'айк'] ], … ]
```

## Асинхронность

Сейчас методы синхронные. Сервер отвечает не сразу, поэтому при встраивании:

- `corpusTotal`, `corpusSources`, `poolSize` — числа для воронки и статистики: забрать один раз
  при монтировании, положить в состояние, методы читают из состояния.
- `wordSuggest` — вызывается по клику на слово: вернуть промис, а до ответа показать в попапе
  скелет из трёх строк (попап уже умеет рисовать пустой список).
- `stanzaPool`, `rhymeFor`, `runTitles` — участвуют в генерации: вызывать до вставки блока,
  дальше отдавать в существующий код уже готовые данные.

## Что не относится к бэкенду

Эти части работают целиком на клиенте и переносить их не нужно:

- документ, история, папки, избранное, корзина — состояние компонента и `localStorage`;
- профили вида и профили сцены — `localStorage` (`nlUiProfiles`, `nlFsProfiles`);
- сцена фристайла — движок `freestyle-engine.js` (визуализатор, пресеты, камера, запись);
- тема, палитра, градиент, зерно — настройки вида.

## Порядок встраивания

1. Реализовать восемь методов поверх реального API, оставив демо-данные на месте.
2. Переключить `api` на реальные вызовы, прогнать: генерация строфы, прогон пайплайна,
   попап по слову на всех пяти вкладках, воронка, статистика, фристайл в обоих режимах источника.
3. Удалить демо-данные и заглушки `suggestList` / `rhymeTail`.
