## Решения прожарки 2026-07-31 (все закрыты)

1. **Шелл** — две вкладки (Редактор / Фристайл), как в дизайне. Генератор живёт внутри редактора: ⌘↵ строфа в каретку, ⌘⇧↵ прогон блоком с листалкой вариантов ‹ › ✓ ×. Отдельной вкладки генератора нет. *Почему: листание вариантов на месте заменяет быстрый цикл; так вылизан дизайн.*
2. **Тема = выделение.** Выделенное слово (или строка) в момент генерации становится ключом-ориентиром; поле темы не появляется. Обратная связь — статусная строка (`ключ: «…»` / `без ключа`). **⌥↵** — принудительное появление ключа (механика `_ensure_forced`, честный отказ). В легенду хоткеев добавляется строка про ⌥↵. *Почему: ноль нового хрома; принудительность и ориентир — два разных жеста.*
3. **Чипы цепочки = профили строф** (переименовываемые; выбор из 24 форм + своих, конструктор уже есть). **Стыки** — три типа из дизайна как реальные ограничения: «рифмовать стык» = рифмо-группа граничных строк, «слом ритма» = слоговой контраст, «свободно» = без связи.
4. **Пайплайн = пулы по звеньям + комбинаторная склейка** (а не N независимых полных прогонов). Два числа в панели: «прогонов» (сколько комбинаций оценить) и «лучших» (сколько показать, по умолчанию 10) — это чинит двусмысленность одного поля лимита в макете. *Критерий успеха, дословно: выдача пайплайна заметно сильнее одиночной генерации; нет разницы на глаз → усиливаем оценку склейки.*
5. **Крутилки:** Точность рифм→`rhyme_precision`, Мелодичность→`melody`, Банальность→`banality`, Источники→`real_text`, Разнообразие→вес разнообразия склейки (своя механика); **Метр выброшен** (пустышка-дубль); Диссонанс (в фильтрах)→`cohesion`; Порог отсева→порог склейки пайплайна; алгоритм ▾ = `classic` 0/1; «без мата» пишется по-честному (корни + pymorphy); «слоги 8–9» = жёсткое сужение диапазонов; «только точные рифмы» = верхний ярус точности.
6. **Листы = настоящие `.md` в настоящих папках**, хранилище `~/Documents/nakedlunch/тексты/`; папки = папки, корзина = служебная подпапка со сроками (30 дн.), умные папки = сохранённые запросы. Четыре упрощения: буквы рифмовки пересчитываются бэкендом (не хранятся); звёзды живут в `corpus.json` (восстанавливаются по тексту); незакрытые прогоны — рабочее состояние, в файл падает текущий вариант; пометки я/nl и закрепы — сессионные. **Приложение называется nakedlunch** (новая версия nakedlunch; extendo — промежуточное имя).
7. **История = только показанное на экране, построчно, везде**: вставленная строфа, вариант прогона в момент листания на него, строка фристайла в момент показа. Теневая генерация и недолистанные варианты не помечаются. Клик по строке истории = вставка в документ БЕЗ воскрешения для генератора.
8. **Звезда = индикатор совпадения с избранным.** Правка строки гасит звезду, но избранное неприкосновенно (старый текст остаётся в коллекции навсегда).
9. **Попап по слову, 5 вкладок:** «строкой» (скан nl_rhyme.json), «рифмы» (предсобранный обратный индекс, ruaccent только на сборке), «по звуку» (согласный скелет + ударный гласный), «синонимы» (navec-ассоциации + словарный слой), «антонимы» (только словарь). Словарь — машиночитаемая выжимка русского Викисловаря (kaikki.org). **Ворота качества: ручная проверка на живых словах ДО включения; мусор → вкладка скрывается, не фейкуется.**
10. **Фристайл переносится точь-в-точь по дизайну** (он вылизан). **Приоритет №1 — аудио-маршрутизация:** синтетика — неслышный водитель по умолчанию → загруженный луп слышен и водит картинку → снял луп → синтетика мгновенно подхватывает, показ не прерывается; микрофон влияет параллельно (Butterchurn суммирует источники — проверено по исходнику, прототип уже гонял оба). Один AudioContext 48 кГц, слышимый тракт прямой, без деградации.
11. **Профили сцены/вида/палитра — файлы в `data/`**, не localStorage (решение раунда 26 действует; localStorage в макете — артефакт среды разработки).
12. **Порядок фаз: ядро → пайплайн → попап → фристайл → запись → переименование.**

## Граница с бэкендом (замена `api.*` из макета)

| Макет | Реальность | Примечание |
|---|---|---|
| `corpusTotal()` / `corpusSources()` / `poolSize()` | `GET /api/nl/state` | фильтровать по `active`; в воронке показывать **обе** цифры пула (total/available) — их разделили сознательно, не сливать обратно |
| `stanzaPool(roleKey)` | `POST /api/generate` | полный параметрический вызов: ключ-из-выделения, крутилки, спека строфы звена, forced-режим |
| `wordSuggest(word, tab, rowIdx)` | `POST /api/word/suggest` | новый роут, фаза 2 |
| `rhymeFor(tail)` | **упраздняется** | рифмовка стыков делается на сервере отбором по рифмо-ключу — строго лучше подмены последнего слова |
| `runTitles()` | клиентская константа | бэкенду тут делать нечего |

Всё асинхронно: состояния загрузки, честные ошибки, офлайн-баннер (демо-режим уже есть). Каждый новый `/api/*` роут регистрируется явно — catch-all в `server.py` отдаёт файлы, незарегистрированный путь = 404-файл, не JSON.

## ФАЗА 0 — ядро (редактор + генерация + листы)

**Фронт** (`interface/react-app/src/`): новый корневой компонент — перенос шаблона дизайна в JSX один-в-один (шелл, обе темы, тонирование/свечение/стекло, панели: пайплайн, фильтры, алгоритм, строфа, листы+папки+корзина, избранное, история, воронка, статистика, легенда). Модель документа (роль/строка, каретка, marks), undo/redo — **готовый компонент, не самописный** (решение старого плана в силе). Хоткеи: ⌘↵, ⌥↵, ⌘⇧↵, ⌘Z/⌘⇧Z, ⌘B/⌘I/⌘1, Alt↑↓, Enter-деление строки. Статусная строка с ключом. Снимок выделения — в момент нажатия, до потери фокуса.

**Бэк:** `core/sheets.py` + роуты `/api/sheets/*` (CRUD листа, папки, корзина со сроками, умные папки, дубликат, переименование, «открыть папку» по образцу nl/open-dir); пересчёт букв рифмовки при открытии листа (существующий `rhyme_key`); фильтр мата в `filters.py`; батч `mark_shown` при показе; воронка → `_rich_funnel` (реальные числа, никакой клиентской арифметики); статистика → `/api/stats`.

**Готово, когда:** ежедневная работа полностью в новом UI. Старый интерфейс удаляется (философия: один источник правды), не раньше паритета ядра.

## ФАЗА 1 — пайплайн (склейка)

`core/pipeline.py` + `POST /api/pipeline/run` (прогресс — через существующий `/api/status`):

1. **Пулы:** на каждый уникальный профиль звена — внутренние вызовы генерации (~50 строф на профиль; генератор отдаёт десятки строф за вызов → весь прогон ≈ 6–8 тёплых вызовов).
2. **Склейка:** перебор/beam по числу «прогонов». Балл = w₁·качество звеньев (средние баллы каскада) + w₂·стыки (ярус совпадения рифмо-ключей / величина слогового контраста) + w₃·штраф повторов лемм поперёк песни. Жёсткие условия (в мусор без балла): схема звена выполнена, слоги в диапазоне, одна строфа не стоит дважды, принудительное слово на месте. Порог отсева = отсечка по баллу склейки.
3. **Выдача:** M лучших блоками в документ, листалка уже в UI. Профили цепочек `{chain, junctions, filters, threshold, limits}` → `data/chain_profiles.json` + CRUD.
4. **Потокобезопасность:** очередь заданий, один прогон за раз (Flask threaded + глобальные сторы без локов — мутации сериализуем).

**Ворота фазы:** живое сравнение с одиночной генерацией. Веса w₁–w₃ крутятся без переписывания архитектуры.

## ФАЗА 2 — попап по слову

`tools/build_rhyme_index.py` (ruaccent на сборке) → `core/data/rhyme_index.json`; `tools/build_thesaurus.py` — выжимка kaikki.org → `data/thesaurus.json`; роут `/api/word/suggest`. Порядок вкладок по нарастанию риска: строкой → рифмы → по звуку → синонимы → антонимы. Частотная колонка — wordfreq. Ворота качества перед включением каждой словарной вкладки.

## ФАЗА 3 — фристайл

`src/freestyle/` — порт прототипа внутрь приложения (`butterchurn`, `butterchurn-presets` в package.json), сцена по дизайну послойно (bc → bloom → цветная панель → scrim → зерно → варп-постфх с трюком уменьшенного рендера из `Freestyle Optimized`). Аудио-граф: state-machine синтетика/луп/микрофон (приоритет №1 фазы, критерий — переключение источников без прерывания показа). Камера с фолбэком. Шрифты: проверенный системный список прототипа + загрузка файла через FontFace; Google Fonts из макета удаляется (офлайн-инвариант). Профили сцены/вида, пресеты (поиск/избранное/недавние) → файлы `data/`.

## ФАЗА 4 — запись

**Сначала спайк качества (≈день):** AudioWorklet-отводы → батчи в Python → WAV с перепрошивкой заголовка; `canvas.captureStream` → MediaRecorder → WebM чистого визуала (без интерфейса); замер дропов, CPU, частоты. 

**Если качество подтверждено** — полная реализация: три раздельные дорожки (`mic.wav`, `loop.wav`, `video.webm`), не пересекаются — для сведения; всё пишется инкрементально, `.partial` + атомарное переименование, сбой посреди записи = валидные файлы короче, любой сбой громкий, health-индикатор; склейка дорожек в одно видео — опциональный пост-процесс через ffmpeg, только если он есть в системе (единственная внешняя опциональная зависимость всего плана).

**Если нет** — запись отдаётся сторонним (OBS), кнопка честно скрывается. Приоритетные функции (луп) не зависят от этой фазы вообще.

## ФИНАЛ — переименование и чистка

**Сделано 2026-08-01:** заголовок окна, `<title>` вкладки, имя npm-пакета → nakedlunch. Сборка и 105 тестов зелёные.

**Переезд каталога СДЕЛАН 2026-08-01** (владелец: «старый нейкедланч сохранён на гитхабе, можно заменять и выпускать как новую версию смело»). Порядок был важен, потому что «просто заменить» сломало бы корпус:

- **Сначала отвязка.** Приложение импортировало код CLI ПО ПУТИ (`sys.path` → `~/nakedlunch/core/{store,generator,cutter}.py`) — то есть каталог CLI был скрытой рантайм-зависимостью, и его исчезновение убило бы корпус, хотя сами данные лежат в другом месте. Замыкание оказалось чистым (1168 строк, три файла, дальше ничего не тянут) и внесено в `core/nlsrc/`; в `store.py` изменены ровно две строки импорта. `NAKEDLUNCH_REPO` вычищен полностью.
- **Потом переезд.** `~/nakedlunch` → `~/nakedlunch-cli` (CLI не удалён — он рабочий и стоит 8 МБ, удалять его ради имени незачем), `~/extendo` → `~/nakedlunch`.
- **Данные не тронуты**: корпус как лежал, так и лежит в `~/Documents/nakedlunch/data` (526 МБ). Приложение и CLI по-прежнему читают один и тот же файл.
- **Проверено после переезда**: venv пережил (его `bin/python` — симлинк на системный), 105 тестов, сборка фронта, сервер поднимается с 52 роутами, корпус 1 958 936 фрагментов. Пути в `~/.claude/launch.json` обновлены, мёртвые записи эфемерного скратчпада вычищены.

**НЕ сделано, требует решения владельца:**

1. **Старый интерфейс УДАЛЯТЬ НЕЛЬЗЯ — он держит функции, которых в новом нет.** Сверка роутов (2026-08-01): старый UI дёргает `/api/nl/source/add`, `/api/nl/source/toggle`, `/api/nl/source/remove` (управление источниками корпуса — то, ЧЕМ корпус растёт), `/api/nl/rhyme/run` (пересборка рифмо-кэша), `/api/nl/clear-used`, `/api/nl/retention`, `/api/history/clear`, `/api/history/restore`, `/api/history/restore_theme`, `/api/history/retention`, `/api/mark`. Новый UI не дёргает ничего из этого. Причина структурная: дизайн «Editor First» покрывает редактор и фристайл, а экрана управления корпусом и историей в нём нет вовсе. Пока не решено, куда это селить, старый UI остаётся доступен по `#old` и работает.

## Наследие старого плана (не потеряно)

- **Спайки 1–4 (2026-07-17): модель вкуса мертва** — AUC≈0.5 на всех мощностях модели; ворота «~300 избранных» для повторного пакета тестов остаются. Оценка склейки пайплайна сознательно строится на объективных баллах каскада + ручной курации выживших, НЕ на модели вкуса — это согласовано с результатами спайков.
- **Крутилка «смысловое столкновение»** (одобрена к постройке на попарном косинусе, спайк-2 тест A) — в 5 ползунков нового дизайна не вошла. ПРИПАРКОВАНА: кандидат в компонент балла склейки (w₄) или шестой ползунок. Решить в фазе 1 по живой выдаче.
- **Автогенератор** (старая ФАЗА 3) — реализуется пайплайном, ворота качества встроены в критерий фазы 1.
- Болт-он «статистика по своим текстам» («как ты пишешь») — припарковано, вернётся, когда в хранилище накопятся тексты.
- Урок протокола: рейты на единицу экспозиции; латентность p95 ≈ 1.2 с — бюджет, в который обязан вписаться прогрев пулов.
